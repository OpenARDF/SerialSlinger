# SerialSlinger 2.0.25

## User-visible changes

- Duration changes made after a schedule has expired now create the requested duration from the next valid five-minute start boundary on Android and desktop.
- The desktop app again detects and loads an attached SignalSlinger automatically at startup.
- Android consistently shows verified transmitter readback after setting changes instead of presenting a requested value that the transmitter did not retain.

## Stability and reliability

- Android setting submissions now share one result handler for success, no-change, transport failure, and verification failure behavior across all editable settings.
- A failed Android verification cannot be reported as success or replace the saved clone template; same-device readback remains visible for diagnosis and is recorded in the session log.
- Schedule-duration calculation is shared by Android and desktop and has regression coverage for expired schedules, including a nine-hour overnight event.

## Android release notes

Fixes duration changes after schedules expire and improves setting verification. Android now displays actual transmitter readback when a requested value is not retained, reports the operation as failed, preserves the clone template, and records the verification details in the log.
